# main의 V2 전환 기록

전환일: 2026-10-10. 대상: `capstone1-irion/simulation`의 `main`.

## 왜 V1을 현재 main에서 제거했는가

사용자가 V2 전체를 main에 반영하고 Git상의 V1을 제거하도록 승인했다. V2는 V1의 import wrapper나 호환 모드가 아닌 독립 재작성이다. 두 실행 체계를 함께 두면 팀원이 예전 명령·설정·검증 기록을 현재 기준으로 오인할 수 있어, main의 실행 기준을 V2 하나로 통일한다.

- V1의 PX4 패치·모터 bridge·overlay 빌드 경로는 원본 PX4/Gazebo를 보존하는 V2 구조와 다르므로 현재 배포에서 제거한다.
- V1 서비스·plugin·기체 설정·테스트·운영 문서는 V1 경로와 계약을 전제로 하므로 V2 파일로 교체한다. 모든 V1 코드가 잘못됐거나 모든 옛 기능이 V2에서 구현됐다는 뜻은 아니다.
- V2는 실행 제어, 모터 명령 중계, 배터리 계산, 수신 전용 수집, 재생/전처리를 구분하고 파일 역할·단위·시계·실패 경계를 한국어로 설명한다.
- 예전 검증 통과를 V2의 증거로 승계하지 않는다. V2 자체 기본 통합 결과와 제외 범위를 `검증결과.md`에 기록한다.
- CMU 기반 네 단계 파생 프로파일 수치와 출처, 모델 설정의 원본 귀속은 V2 구조와 `THIRD_PARTY_NOTICES.md`에 유지한다.

V1 전용 저장소 템플릿과 루트 보조 설정도 V2 소유 파일 목록에 맞춰 제거한다. 제거는 main의 현재 파일 트리에 대한 것이며 GitHub 저장소·이슈·PR이나 다른 원격 브랜치를 삭제하는 작업이 아니다.

## 보존하는 것

- 전환 직전 main: `22cab929a32dcc48971a44e18f600e170e836117`.
- 이 커밋을 부모로 하는 일반 후속 커밋으로 전환한다. force-push·orphan 이력·과거 커밋 삭제는 하지 않는다. 과거 V1은 Git 이력에서 조회할 수 있다.
- 로컬 이전 프로젝트 `/home/sa/Capstone`과 그 안의 미커밋 변경·환경·원자료는 수정/삭제하지 않는다.
- V2의 원본 의존성 checkout, 설치 환경, 기존 실패/성공 원시 로그도 로컬에 보존한다.

복원이 필요하면 별도 checkout에서 위 커밋을 조회하거나 전환 커밋의 revert를 검토한다. 로컬 미커밋 파일이 있는 V1에 reset/checkout을 강제하지 않는다.

## Git에 포함하는 것과 제외하는 것

포함: `main.py`, `capstone/`, `native/`, `config/`, `models/`, `profiles/`, `tests/`, `tools/`, `docs/`, 빌드 정의·Python 버전 고정 파일·운영/설계/검증/귀속 문서·작업 규칙.

제외: `external/` 원본 checkout, `.venv/`, `hermes/` 조사·빌드·실행 부산물, 기업 `log/` 및 BIN/ULog 원자료, 캐시·로컬 빌드·비밀정보. V2 전체 배포는 제출 가능한 소스·설정·문서 전체를 뜻하며 설치된 컴퓨터 환경이나 기업 원자료 업로드를 뜻하지 않는다.

원시 검증 로그는 clone에 없으므로 문서의 `hermes/...` 경로는 개발 PC의 보존 증거 위치다. 새 PC에서는 `docs/설치와실행.md`에 따라 의존성을 설치하고 빌드한다. 다른 PC 설치 재현을 이번 전환으로 검증했다고 주장하지 않는다.

## 완료 범위와 후속 과제

- 완료: 승인된 V2 시뮬레이션·모터1 고장·배터리 프로파일·수집·전처리의 기본 통합 검증, headless 운영 경로.
- 별도 한계: Gazebo GUI 종료 실패, 모터2~4 개별 고장 비행, 직접 연결 대비 지연/동등성, 장시간·모든 단절/reset, 타 PC 재현.
- 후속 개발: 탐지 목표/고장 정의와 데이터 조건 합의, 시뮬레이션 데이터셋, 모델 2종 학습/비교, 경보 평가, 실시간 UI.
- 기업 BIN은 관측 항목·단위·기록 주기 참고용이다. 학습/검증/시험 데이터나 라벨 확보 과제로 지정하지 않았다.

이번 전환은 문서와 배포 구성 작업이다. 제품 계산/제어 코드를 변경하거나 새 시뮬레이션·통합 시험을 실행하지 않는다. 배포 점검은 파일 목록·문서 링크·제외 규칙·diff와 원격 main 커밋/트리 대조로 수행한다.
