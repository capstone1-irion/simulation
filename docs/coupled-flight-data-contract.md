# 커스텀 모터·배터리 텔레메트리 입력 명세

## 목적과 지원 조건

수집·AI·UI는 PX4가 송신한 표준 MAVLink 값을 받는다. Gazebo 원본 관측은 전달 대조용이며 AI 실시간 입력을 우회하지 않는다. 실기체 최소 지원 조건은 유효한 배터리 전압·전류 측정이다. 모터별 상태를 사용하는 기능은 해당 ESC 텔레메트리와 PX4 드라이버 지원을 추가로 요구한다. 실기체 연결·AI 탐지 성능을 검증한 문서가 아니다.

## 입력 필드

| 대상 | 원본 | 정규화 및 의미 | 제한 |
| --- | --- | --- | --- |
| 배터리 전압 | `BATTERY_STATUS.voltages`, 필요 시 확장 슬롯 | 알려진 전압 슬롯의 mV를 해석해 pack V로 구성 | 이번 모델은 같은 전압의 4셀. 실기체에서는 첫 슬롯이 전체 팩 전압일 수 있으므로 개별 셀 센서로 단정하지 않는다 |
| 배터리 전류 | `BATTERY_STATUS.current_battery` | cA → A | 이번 모델은 방전 전류만. 미상값 -1은 측정값으로 사용하지 않는다 |
| 사용 전하량 | `BATTERY_STATUS.current_consumed` | mAh | 정격용량이 아니다. 미상값 -1 제외 |
| 잔량 | `BATTERY_STATUS.battery_remaining` | % | 이번 시뮬레이터의 모델 SOC를 반영한 값. 실기체의 추정 오차와 동일하다는 보장은 없다. 선택 입력 |
| 모터 회전수 | `ESC_STATUS.rpm` | RPM, `index`부터 시작하는 ESC 슬롯 | 명령값과 상태값을 구분하고 실제 생산 경로는 모델 설명을 따른다 |
| 모터 전류·전압 | `ESC_STATUS.current`, `voltage` | A, V | ESC 텔레메트리 지원 조건. 이번 전류 모델은 제공된 16V 벤치 표 기반 근사 |
| 식별 | MAVLink header system/component, battery ID, ESC index | 실행별 송신자·부품 식별 | PX4 autopilot component=1만 기본 입력. 외부 battery injector component=180은 별도 기록/제외 |

현재 초기 연동은 모터 부하 → 배터리 상태의 단방향이다. 배터리 전압 저하가 기체 추진력·모터 구동 명령을 제한하는 완전한 전기·기계 결합은 구현 범위가 아니다.

## AI 입력에서 제외할 값

- 모델 내부에 설정한 정답 용량·내부저항, 고장 주입값, 정답 상태/구간.
- 실행 도구의 `phase`도 실험 구간 표식이다. 배터리/모터 이상 여부를 미리 알려주는 AI 입력으로 넣지 않는다.
- 초기 모델에서 고정한 온도. 이것을 실제 온도 센서 또는 열 모델로 취급하지 않는다.
- 벤치 표 밖 근사 구간의 값을 실측값 또는 검증된 실기체 보정으로 취급하지 않는다.
- 정격용량은 배터리별 구성 정보로 분리한다. 내부저항은 추후 전압·전류로 추정한다면 추정 품질 정보와 함께 별도 특징으로 취급한다.

## 시간과 갱신

- `mavlink_raw.jsonl`은 수신 UTC ns와 monotonic ns, 단계(phase), 송신자, 원본 디코딩 필드를 보존한다. 수집 소켓은 MAVLink 패킷을 전송하지 않는다.
- `ESC_STATUS.time_usec`는 PX4 측 시각이다. 배터리 메시지에는 동일한 원본 시각 필드가 없으므로 수신 시각을 측정 시각이라고 부르지 않는다.
- `producer.jsonl`은 Gazebo frame의 simulation ns와 읽기 전용 관측 시각을 별도로 보존한다. `sender.jsonl`의 `udp_sent`는 로컬 UDP 쓰기 성공이지 PX4 수신 성공이 아니다.
- 목표 발행률은 모터 20Hz, 배터리 5Hz이며, 실제 수신률과 데이터 양은 각 실행 원문/보고서에서 계산한다. 목표 주파수를 관측값으로 기록하지 않는다.
- 누락/미상/비유한 값은 정상 0으로 채우지 않는다. 초기 수집기는 원문 보존이며, 고정 길이 창 보간·정규화·지연 허용치를 AI팀이 확정하기 전 학습용 동기화 완료로 취급하지 않는다.
- 원래 표본보다 높은 빈도로 값을 유지해도 새 센서 측정이 생기는 것은 아니다. 향후 전처리는 인과적으로 수행하고, 긴 공백은 유효하지 않은 창으로 구분한다.

## 파일과 검증 범위

| 파일 | 용도 |
| --- | --- |
| `report.json` | 실제 전달/비행 판정, 설정, 단계별 수치, 정리 결과 |
| `mavlink_raw.jsonl` | PX4 출력과 기타 송신자를 구분한 실제 수신 원문 |
| `producer.jsonl` | Gazebo Plugin 원본 상태 대조용 |
| `sender.jsonl` | 배터리 wire 단위 변환·송신 시각 대조용 |
| `px4.log`, `gazebo.log` | 소유 시뮬레이터 콘솔·서버 원문 |
| `rootfs/log/` | PX4가 생성한 경우 보조 ULog. 필수 AI 실시간 입력이 아님 |

`report.json`의 통과는 그 실행이 실제로 확인한 범위에 한정한다. 실기체 호환 전체, 팩/모터 물리 보정, 이상탐지 정확도 또는 안전 인증을 의미하지 않는다.

## 2026-10-04 실제 수신 기준선

성공한 `flight-zgit9bn0` 원문을 별도로 다시 읽어 계산했다. 전체 디코딩 기록1458개 중 ESC_STATUS635개, BATTERY_STATUS165개다. 다른 상태/이벤트 메시지도 포함된 전체 개수를 전부 모터·배터리 표본으로 세지 않는다.

| 호버 메시지 | 관측 개수 | 실제 수신률 | 최대 수신 간격 |
| --- | --- | --- | --- |
| ESC_STATUS | 155 | 19.231 Hz | 0.052630049 s |
| BATTERY_STATUS | 40 | 4.999955 Hz | 0.200304297 s |

- 수신률은 `(개수-1)/(마지막-첫 수신 monotonic 시각)`이다. Plugin의 sim-time 실제 간격은 모터0.052s·배터리0.2s였다.4ms timestep에서20Hz 목표가52ms로 양자화되므로 정확한20Hz 고정 간격을 가정하지 않는다.
- 이번 비행의 ESC RPM은 joint feedback 기반이며 `allow_command_fallback=false`로 실행했다. ESC 전압은 배터리의 같은 모델 terminal voltage, 전류는16V 벤치 기반 근사다. 배터리 sag에 맞춰 전류/추진력을 다시 계산하는 양방향 모델은 아니다.
- 호버 배터리40개는 sender wire 값과, ESC155개는 수신 시각 차이300ms 이내의 producer RPM/V/A와 대조했다.300ms는 이 전달 대조의 후보 검색 창이지 실기체 지연 상한 또는 AI 운영 timeout 인증이 아니다.
- 배터리는 MAVLink에 원본 측정 시각이 없으므로 수신 시각만으로 정확한 센서 지연을 계산하지 않는다. 유효한 ESC `time_usec`와 수신 시각은 별도 보존한다. 같은 원본 시각/값의 재송신은 독립 측정으로 부풀리지 않는다.
- 원문 수집 계약은 결측을 지우거나0으로 대체하지 않는다. 오프라인/실시간 전처리는 동일한 인과적 규칙·허용 공백·window 유효성 정책을 별도로 버전 관리해야 한다. 현재 raw collector가 그 학습 전처리를 구현했다고 표시하지 않는다.
- 실기체에서는 BATTERY_STATUS 전류/온도/잔량의 미상 sentinel, ESC 드라이버의 필드 가용성을 별도로 확인한다. 이 시뮬레이터가 보낸 유효 숫자만으로 실기체의 모든 필드 지원을 보장하지 않는다.

근거: 작업폴더 `hermes/coupled-flight/runtime-readback.json`, 성공 실행의 원문4파일, 호버 uORB snapshot. 기준선은 정상 짧은1회이며 반복성·실기체 검증 결과가 아니다.
