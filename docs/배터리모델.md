# 명령 기반 배터리 계산과 CMU 프로파일

상태: **세 번째 통합에서 계산 단위 검사·pause 적분 정지·기준/후기 프로파일 비행·PX4 배터리 재출력 대응을 확인했다.** 정상/모터/후기 run에서 각각147/177/150개 모델-wire 대응 표본을 확인했고 wire ID255를 관측했다. 결과는 루트 `검증결과.md`를 따른다. 이는 구현/연결 검증이며 물리 모델의 현실 적합성·실기체 팩 보정·정밀 전기/추력 결합 검증은 아니다.

## 1. 무엇을 계산하는가

`capstone/battery.py`는 **PX4가 원래 요구한 모터 명령 네 개**로 부하를 근사하고, 시작 전에 고른 배터리 프로파일로 팩 전압·전류·SOC·누적 소비를 계산한다. Python 표준 라이브러리만 사용하며 V1 모듈, Gazebo, MAVLink를 import하지 않는다. 원본 `/home/sa/Capstone`이 없어도 V2 코드와 배포한 JSON만으로 계산하도록 작성했다.

- 입력 명령은 `rad/s` 단위 각속도 목표값이다. 실제 joint 속도, RPM 센서, ESC duty, 측정 전류가 아니다.
- 고장 중계 **전**의 원래 명령을 쓴다. 모터 고장 이후 실제 전기 소비를 알아낸다는 뜻이 아니다.
- 모터 고장 실험에는 초기 기준 배터리를 쓰고, 배터리 프로파일 비교에서는 모터 고장을 끈다. 복합 고장 실험을 이 모델로 검증했다고 하지 않는다.
- 전압은 보고용 계산값이다. 전압 저하를 모터 힘이나 소비전류에 되먹임하지 않는다.
- 프로파일과 초기 SOC는 새 run을 만들기 **전**에 정한다. 모델은 Disarmed 여부를 알지 못하므로 시작 시점 확인은 실행 제어자의 책임이다. 실행 도중 교체·reset·restore API는 없다.
- SOC는 선택한 용량에서 남은 충전 비율이다. 상대 용량 SOH와 다르다. SOH·프로파일 ID·용량·저항은 설정/정답 메타데이터이지 AI 관측 특징이 아니다.

## 2. 파일 역할과 읽는 순서

| 순서 | 파일 | 역할 |
|---|---|---|
| 1 | 이 문서 | 단위, 계산, 실패와 근거의 경계 |
| 2 | `profiles/load.json` | 명령 정규화, 16 V 전류표, 보조부하, 공백 한도와 그 가정 |
| 3 | `profiles/battery/cmu_vah01_rpt000.json` 등 네 JSON | 짧은 런타임 파라미터와 **완전한 SOC/OCV 배열** |
| 4 | `capstone/battery.py` | 입력 검사 → 전류 → 시간 적분 → 전압 → 상태 반영 |
| 5 | `profiles/battery/provenance.json` | V1 출처·추출/잔차·원본 행·기존 검증 주장과 이번 이전 식별 정보 |
| 6 | `tests/test_battery.py` | 코드/문서 작성 후 통합 검증에 포함해 실행하는 계산·데이터 보존 단위시험 |

`battery_link`는 별도 책임이다. 원래 명령과 시뮬레이션 시각을 수신하고 신선도를 확인하여 이 계산기를 호출한 뒤, 표준 `BATTERY_STATUS` 송신을 담당한다. 순수 계산기에 연결/전송/프로세스 종료 기능을 섞지 않았다.

## 3. 고정된 Python API

```python
load_profile(profile_id_or_path, profiles_dir=None) -> dict
Battery(profile, initial_soc=0.95, load_config=None)
battery.update(command_rad_s, sim_time_s) -> dict
```

### 프로파일 읽기

- `profile_id_or_path`는 정확한 ID 문자열 또는 JSON 경로(`str`/`pathlib.Path`)다.
- `Path` 객체는 항상 경로다. 문자열에 `/`가 있거나 `.json`으로 끝나면 명시적 경로로 읽고, 그 외 문자열은 ID로 처리한다. 상대 경로는 현재 작업 폴더 기준이다.
- ID는 영숫자로 시작하는 길이 1~64의 ASCII 영숫자·밑줄·하이픈·점이다. 공백 제거, 대소문자 변환, 유사 ID 추측을 하지 않는다.
- `profiles_dir=None`은 모듈 위치를 기준으로 한 `profiles/battery`다. ID는 그 폴더의 `<id>.json`에서 읽고 내부 `id` 일치도 검사한다. 명시적 경로에는 `profiles_dir`를 적용하지 않는다.
- 반환형은 **plain dict**다. 최소 계산 필드는 `id`, `capacity_ah`, `pack_resistance_ohm`, `series_cells`, `ocv_soc`, `ocv_cell_v`다. 배포 파일에는 원래 `label_ko`, `initial_soc`, `soh_percent`와 `parallel_cells`, 출처 참조도 있다.
- `schema`가 있으면 `capstone.battery_profile.v1`만 허용한다. 용량·저항·셀 전압은 양수/유한 수여야 한다. 직렬 수와 주어진 병렬 수는 양의 정수여야 한다.
- SOC 축은 0부터 1까지 엄격히 증가하며 배열 길이는 서로 같고 2점 이상이어야 한다. 중복 축, 빠진 끝점, NaN/Inf, 잘못된 단위를 암시하는 문자열을 받아 정상값으로 고치지 않는다. 전압을 임의 단조화하지 않는다.
- 파일 누락은 `FileNotFoundError`, 잘못된 JSON/내용/ID는 `ValueError`다. 초기 프로파일로 자동 대체하지 않는다.

### 새 run 생성

`Battery`는 프로파일의 수치와 곡선을 자기 상태로 보관한다. 초기 소비량은 0 mAh다. 생성 후 입력 dict/배열을 변경해도 객체의 계산에는 반영되지 않는다. `profile_id`, `series_cells`는 읽기 전용 속성이다.

`initial_soc` 인수가 실제 시작 상태를 결정한다. 파일의 `initial_soc=0.95`는 보존된 V1 기본 가정이며 인수를 무시하는 숨은 설정이 아니다. 다른 시작값은 새 객체에 명시해야 한다.

`load_config=None`이면 모듈 위치 기준 `profiles/load.json`을 읽는다. 직접 설정하려면 **전체 plain dict**를 준다. 필요한 키는 `command_max_rad_s`, `auxiliary_current_a`, `max_gap_s`, `bench_voltage_v`, `throttle`, `motor_current_a`다. 누락 키를 기본값과 합치지 않으며 `{}`도 오류다. `schema`가 있으면 `capstone.command_load.v1`이어야 한다. 별도 프로파일 폴더를 지정했다고 부하 파일 위치도 바뀌지는 않는다.

### 반환 샘플

| 키 | 단위/의미 |
|---|---|
| `voltage_v` | 부하가 걸린 가상 팩 단자전압 V |
| `current_a` | 현재 명령에서 추정한 팩 방전 전류 A, 방전이 양수 |
| `soc` | 0~1 충전 비율, percent가 아님 |
| `consumed_mah` | 이 run에서 시작 후 소비한 mAh, 초기 가용 전하까지만 누적 |
| `sim_time_s` | 전달받은 시뮬레이션 초, Unix 시간/벽시계가 아님 |

반환형은 이 **다섯 키만 갖는 plain dict**다. 반환 dict 변경으로 모델 상태를 바꿀 수 없다. 온도, 셀별 실측 전압, RPM, SOH나 프로파일 ID를 배터리 관측값처럼 함께 내보내지 않는다.

호출 흐름 예시이며 작성 중 실행한 결과가 아니다.

```python
from capstone.battery import Battery, load_profile

profile = load_profile("cmu_vah01_rpt002")
battery = Battery(profile, initial_soc=0.95)
first = battery.update([500.0, 500.0, 500.0, 500.0], 10.0)
next_sample = battery.update([520.0, 520.0, 520.0, 520.0], 10.1)
```

## 4. 명령 → 부하: 보정된 전기 모델이 아닌 명시적 근사

각 명령 `w`를 다음처럼 정규화한다.

```text
u = min(w, command_max_rad_s) / command_max_rad_s
기본 command_max_rad_s = 1000 rad/s
I_pack = I_motor(u0) + I_motor(u1) + I_motor(u2) + I_motor(u3) + 0.5 A
```

입력은 정확히 네 요소의 list/tuple이어야 한다. `None`, NaN/Inf, 음수, bool, 숫자 문자열을 거부한다. 유한한 1000 rad/s 초과 명령은 상한에 제한한다. 이는 V1과 같은 정규화 가정이지, 초과 영역의 벤치 외삽이 아니다. 신선한 네 0 명령은 유효한 정지 명령이며 가정한 보조부하만 소비한다. **누락 명령을 네 0으로 만들어서는 안 된다.**

`profiles/load.json`은 V1의 사용자 제공 `X500MotorSpec.png`를 옮겨 적은 `X500_모터_사양_확인.md`와 `CoupledPowerModel.hpp`의 **AIR2216II-KV920 + T1045II, 16 V** 표에서 30~100%의 15개 throttle/current 쌍을 그대로 보존했다. V2에서 새 벤치 측정이나 원본 이미지 재판독을 한 것이 아니다. 이미지와 문서의 현재 로컬 SHA-256은 기록했으며 원본 이미지는 복제하지 않았다.

- 30~100%: 인접 두 표 점을 선형 보간한다.
- 0~30% 미만: `I_motor = 1.44 × (u / 0.30)²`. 이 구간은 측정이 아니라 **V1에서 유지한 이차식 가정**이다.
- 보조 0.5 A: 측정된 항전장비 전류가 아니라 **기존 상수 가정**이다. 새로운 실측 근거로 포장하지 않는다.
- 16 V: 표의 시험 조건이다. 계산된 현재 배터리 전압에 맞춰 전류표를 다시 보정하지 않는다. 실제 duty/추력 비율에 대한 정량 보정도 없다.
- 1000 rad/s: 고정 PX4 소스에 연결된 x500 SDF의 네 `maxRotVelocity` 값을 읽어 채택했다. PX4와 모델 저장소 commit, SDF SHA-256은 부하 파일에 있다. 모터 회전속도 측정 범위로 바꾸어 설명하지 않는다.

## 5. 시각·적분·실패 처리

**기본 공백 한도는 시뮬레이션 시간 0.5초(`max_gap_s`)다.** 배터리 물성이나 네트워크 벽시계 제한이 아니라, 알 수 없는 긴 구간의 부하를 정상 적분하지 않기 위한 V2 정책이다.

| 입력 상황 | 동작 |
|---|---|
| 첫 유효 샘플 | 해당 시각을 원점으로 삼고 적분하지 않음. 시작 시각 이전 부하를 추정하지 않음 |
| `0 < dt <= 0.5 s` | 직전 유효 샘플의 전류를 해당 구간 동안 유지했다고 가정하여 적분 |
| 같은 시각 `dt=0` | pause/중복으로 소비량·SOC 불변. 새 명령의 순간 전류·전압은 갱신 가능 |
| 시각 역행 | 자동 reset하지 않고 `ValueError`; 새 run 필요 |
| `dt > 0.5 s` | 공백을 채우거나 잘라 적분하지 않고 `ValueError`; 새 run 필요 |
| 결측/잘못된 명령·시각 | 정상 0이나 직전 출력 대신 `ValueError` |
| 비유한 계산/0 이하 전압 | 정상 전압 하한으로 덮지 않고 `ValueError` |

한 번 `update` 오류가 나면 그 객체는 이후 호출에도 오류를 낸다. 마지막으로 유효했던 전하/시각을 소급 수정하지 않지만, 그 상태를 현재의 정상 샘플로 반환하지도 않는다. 호출자는 **run 실패를 기록하고 종료**해야 한다. 비행 도중 새 `Battery`를 만들어 소비량을 지우며 이어가는 복구는 승인된 동작이 아니다.

모델은 전달된 값만으로 명령의 수신 벽시계 나이나 누락된 패킷 수를 알 수 없다. 따라서 연결부는 실제 새 프레임 여부와 벽시계 신선도를 따로 확인해야 한다. 시뮬레이션 시각만 올리면서 오래된 캐시 명령을 계속 넣지 않는다. pause 동안 긴 벽시계가 흘렀더라도 시뮬레이션 시간이 그대로면 이 모델의 적분은 0이다.

```text
dt = 현재 sim_time_s - 직전 유효 sim_time_s
ΔmAh = 직전 유효 I_pack × dt / 3.6
consumed_mah = min(초기_SOC × capacity_ah × 1000, 기존 consumed_mah + ΔmAh)
SOC = clamp(초기_SOC - consumed_mah / (capacity_ah × 1000), 0, 1)
```

적분의 왼쪽 구간 유지 방식은 명시적인 이산 근사다. 새 명령이 들어온 순간부터 순간 전류는 바뀌지만 새 전류를 이미 지난 구간 전체에 소급 적용하지 않는다. 공백 한도 안의 실제 전류 파형까지 관측했다는 뜻은 아니다.

## 6. SOC → 전압

SOC가 두 표 지점 `s0`, `s1` 사이이면 다음 계산을 한다.

```text
f = (SOC - s0) / (s1 - s0)
OCV_cell = V0 + f × (V1 - V0)
V_pack = series_cells × OCV_cell - I_pack × pack_resistance_ohm
```

표의 양 끝점에서는 그 끝점 값을 쓴다. 곡선을 외삽하거나 매끈하게 다시 만들지 않는다. 용량 Ah와 저항 Ω는 이미 팩 기준이며, 병렬 수를 다시 곱하거나 저항에 직렬 수를 중복 적용하지 않는다.

0 이하 단자전압은 모델/부하 적용 범위 오류다. V1의 wire-safe 0.004 V 바닥값은 가져오지 않았다. SOC가 0에 도달하면 누적 소비는 초기 가용 전하에 고정된다. 그래도 `current_a`는 **요구 부하 근사**이고 물리적인 공급 전류/차단기 동작이 아니다. 운영 측에서는 SOC=0을 실험 종료 조건으로 다루며, 빈 팩으로 계속 추진 가능하다고 해석하지 않는다.

온도 모델은 없다. 고정 25°C를 측정값처럼 반환하지 않는다. 외부 sender는 표준 MAVLink `BATTERY_STATUS.temperature`의 **`INT16_MAX` unknown sentinel**을 써야 한다. 다른 음수/고정 정상 온도를 대신 사용하지 않는다. 이 규칙은 고정 소스의 `src/modules/mavlink/mavlink/message_definitions/v1.0/common.xml`에서 확인한 필드 정의이며, 실제 PX4 수신/재송신 동작 검증은 별도 최종 통합 항목이다.

## 7. 보존한 네 프로파일

다음 값은 V1 catalog의 파생 수치를 그대로 옮긴 것이다. 표를 새 원자료 추출 결과로 읽지 않는다. 각 JSON에는 0~1의 **SOC 101점과 대응 셀 등가 OCV 101점 전체**가 들어 있다.

| ID | 팩 Ah | 팩 Ω | 같은 셀 초기 대비 상대 용량 % |
|---|---:|---:|---:|
| `cmu_vah01_rpt000` | 6.178676149834232 | 0.04615530988203852 | 100.0 |
| `cmu_vah01_rpt002` | 5.871438083050888 | 0.045534174816292114 | 95.02744504918603 |
| `cmu_vah01_rpt006` | 5.586921940178748 | 0.0508360108368731 | 90.42263754718137 |
| `cmu_vah01_rpt013` | 5.240295514286093 | 0.05836240894542594 | 84.81259394743783 |

**RPT002도 유지했다.** 그 저항이 초기보다 약간 작은 원래 결과도 유지한다. 열화 순서에 맞춰 저항을 올리거나 용량 scalar로 새 단계를 합성하지 않았다. 런타임 ID와 원래 한국어 label, 초기 SOC, 상대 SOH 소수값도 보존했다.

V1 기록에 따르면 자료는 CMU eVTOL **version 3**, 셀 **VAH01 하나**의 서로 다른 RPT 단계다. 서로 독립적인 네 셀이나 네 실제 기체 팩이 아니다. 4S2P는 동일 셀 특성을 복제한 **가상 팩 설계 가정**이다.

보존된 추출 설명은 셀 용량을 해당 RPT의 방전 전하 counter에서 얻고, 두 C/5→C/50 전류 변화에서 유효 DC 1초 저항을 추정하며, C/5 단자전압에 I×R을 더한 SOC별 등가곡선을 만든 것이다. 이는 V1의 설명을 유지한 것이며 이번에 과학 계산을 재수행한 주장이 아니다.

한계도 함께 보존한다.

- 상대 SOH는 해당 셀 첫 완전 RPT 대비 용량 비율이다. 절대 SOH 인증이 아니다.
- 곡선은 평형 OCV 실측이 아니다. 분극·히스테리시스·온도 영향이 남는다.
- 곡선 SOC=0은 해당 C/5 시험의 2.5 V 부하 차단점 기준이다. 화학적 완전 방전이나 고부하 비행 가능 경계가 아니다.
- 작은 전류 step의 일정 저항을 높은 팩 부하에 적용하는 것은 단순화다. 같은 SOC·온도의 정밀 저항 비교나 고부하 팩 보정이 아니다.
- RC 완화, 온도, 셀 불균형, 방전율별 용량, 연속 열화, 수명 예측, 전압→추력 피드백을 모델링하지 않는다.
- 같은 셀 단계 네 개를 독립 train/validation/test 셀로 취급하지 않는다. AI 학습은 범위 밖이다.

## 8. 출처·라이선스·이전 무결성

원자료 귀속은 **Alexander Bills et al., eVTOL Battery Dataset, Carnegie Mellon University, version 3**, DOI `10.1184/R1/14226830.v3`, 라이선스 **CC BY 4.0**이다. V1의 귀속/라이선스와 고정 원본 URL을 각 `retained_v1_profile_sources` 객체에 그대로 보존했다. 이번 작업은 이미 파생된 수치의 파일 구조 분리이며 원자료 재분석이나 저자들의 V2 모델 보증을 뜻하지 않는다.

- 고정 데이터셋 메타데이터: `https://api.figshare.com/v2/articles/14226830/versions/3`
- 라이선스 원문: `https://creativecommons.org/licenses/by/4.0/`
- 기존 설명: V1 `simulation/docs/cmu-runtime-profiles.md`
- 런타임 데이터 출처: V1 `simulation/profiles/battery/cmu_runtime/catalog.json`
- 추출 provenance 출처: V1 `simulation/profiles/battery/cmu_runtime/provenance.json`
- 명령 부하 근거: V1 `X500_모터_사양_확인.md`, `simulation/docs/coupled-power-model.md`, `simulation/include/arion/CoupledPowerModel.hpp`

`profiles/battery/provenance.json`의 구분은 다음과 같다.

| 구역 | 의미 |
|---|---|
| `migration` | 이번 분리 방법, 보존 ID, 로컬 입력/새 런타임 파일 hash, 원자료 재도출·제품 실행 미수행 표시 |
| `retained_v1_catalog_metadata` | 원래 catalog의 schema, 직렬/병렬 수, 기본 ID |
| `retained_v1_profile_sources` | 네 원래 `source` 객체 전부: 원자료 식별자, 귀속/라이선스, RPT 행 범위, 저항 적합과 곡선 잔차, 보간 원본 행 등 |
| `retained_v1_provenance` | 원래 provenance 객체 전부: 전체 RPT 목록, 선택 근거, 가정, 원본/산출물 hash와 과거 검증 주장 |

**`whole_file_md5_verified=true` 같은 보존 필드는 V1 당시 주장이다. V2에서 raw 파일을 다시 취득·검증했다는 뜻이 아니다.** V1 설명상 원자료와 과거 검증 로그는 로컬 정리 후 미보관이다. 이번에는 제공된 파생 JSON을 읽고 나누었을 뿐, raw CMU 과학 추출기나 제품 모듈을 실행하지 않았다. API의 지정 version 메타데이터에서 라이선스를 조회한 것 역시 raw 내용의 재검증이 아니다.

실제로 읽은 로컬 이전 입력의 SHA-256은 다음과 같다.

```text
catalog.json    a463871205608cb01b31000b46e07e7362c88a8318cb2e601901a837de00427f
provenance.json dbc6db76f0c4c2e1bac43bac29b3ca5cf6c057b0d802454e9957966a9e59cf46
```

각 런타임 파일 hash와 원래 프로파일 payload의 canonical JSON hash도 `migration`에 있다. 최종 시험은 새 런타임 필드와 보존 `source`를 합쳐 **원래 catalog 전체의 canonical hash**와 비교하도록 작성했다. 배열 일부만 비교하거나 V1 저장소가 있어야만 돌아가는 시험으로 만들지 않았다. canonical JSON은 UTF-8, `ensure_ascii=False`, `sort_keys=True`, `separators=(",", ":")`, `allow_nan=False`, 끝 개행 없음으로 정의한다. 이는 파일 이전 수치 보존 검사이지 원자료 과학 타당성 검증이 아니다.

보존된 `curve_csv` 이름과 CSV artifact hash는 V1 산출물 식별자다. V2는 내장 배열을 쓰므로 그 CSV를 별도로 복사하지 않는다. V1 코드를 import하거나 경로를 따라 런타임에 읽지도 않는다. 전류표 원본 이미지에는 확인된 재배포 라이선스가 없으므로 새 오픈 라이선스를 주장하지 않는다.

## 9. 작성한 시험과 남은 검증

`tests/test_battery.py`에는 네 프로파일/전체 곡선 보존, JSON 경로/ID, 양수 파라미터/정렬 검사, 모든 벤치 점·보간·저스로틀·상한, OCV 보간·저항 강하, 첫 표본·인과적 적분·pause·고갈 경계, 결측·비유한·음수·긴 공백·역행의 run 실패, 입력/반환 dict 변경 차단을 작성했다. 합성 단위시험 곡선은 `synthetic_test_only`로 표시해 CMU 실측과 구분했다.

**2026-10-09의 승인된 세 번째 통합 검증에서 배터리 단위검사를 포함한 Python 62개, 빌드와 실제 비행을 수행했다.** 기준/후기 프로파일, 명령·시계 전달, pause 소비 정지, 표준 배터리 송신과 PX4 재송신을 확인했다. 상세 결과는 루트 `검증결과.md`를 따른다. 실제 팩 보정·정밀 전기/추력 결합·장시간 내구성까지 검증한 것은 아니다. 실패 기록은 보존하고 추가 검증은 승인 없이 반복하지 않는다.

현재 전류는 원래 모터 명령·공통 부하표·보조부하로 결정된다. 같은 명령에서 배터리 프로파일만 바꾸면 SOC/전압은 달라질 수 있지만 독립적인 추가 전류 이상이 생성되는 것은 아니다. 추가 소모 탐지가 목표라면 고장 정의와 생성 방식을 먼저 합의해야 하며, 추가 부하 모델은 현재 승인·구현 범위에 포함되지 않는다.
