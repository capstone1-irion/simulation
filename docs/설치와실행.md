# 설치와 실행

이 안내는 **Ubuntu 24.04 / Python 3.12 / Gazebo Harmonic / PX4 v1.17.0**용이다. 팀원이 일반 터미널에서 실행할 수 있으며 Hermes 프로그램은 필요 없다. `hermes/`는 이 프로젝트에서 빌드·실험 산출물을 모으는 폴더 이름이다. 현재 검증 상태는 루트 `검증결과.md`를 먼저 확인한다.

## 1. 어떤 프로그램이 필요한가

| 구성 | 하는 일 | 설치/저장 위치 |
|---|---|---|
| PX4 SITL | 실제 펌웨어의 PC 버전으로 자세·위치 제어와 MAVLink 처리를 수행 | `external/PX4-Autopilot` 원본, `hermes/build/px4` 빌드 |
| Gazebo Harmonic | 가상 기체의 물리와 센서 계산 | Ubuntu 시스템 패키지 |
| CMake·Ninja·C++ 컴파일러 | PX4와 V2 중계 plugin을 실행 파일로 변환 | Ubuntu 시스템 패키지 |
| Python 가상환경 | 배터리·기록·재생·전처리, PX4 빌드 도구 | `.venv/` |
| pymavlink | MAVLink 메시지 인코딩/해석, DataFlash BIN 읽기 | `.venv/` |
| `motor_fault` | 정상/고장에 같은 경로를 유지하는 Gazebo 모터 명령 중계 | V2 소스 `native/`, 빌드 `hermes/build/native` |
| QGroundControl | 별도 관제 UI. 이번 CLI 실험의 필수 프로그램이 아님 | 이 안내에서 설치/설정하지 않음 |

PX4와 Gazebo를 독립적으로 시작하여 기존 모델에 연결하는 공식 경로를 이용한다. 원본 PX4에 V2 코드를 삽입하지 않는다.[1] Harmonic의 Ubuntu 24.04 바이너리는 OSRF 패키지 저장소에서 제공된다.[2]

아래는 **처음 설치하는 PC용 순서**다. 이미 준비된 PC에서 시스템 설치·clone을 다시 실행하지 않는다. 공유 저장소는 비공개이므로 GitHub 접근 권한과 본인의 인증이 필요하다. 비밀번호나 토큰을 명령문/문서에 붙이지 않는다. 새 폴더에 main의 V2를 받는다. 기존 V1 checkout 위에 덮어쓰지 않는다.

```sh
mkdir -p ~/capstone-workspace
cd ~/capstone-workspace
timeout --kill-after=5s 120s git clone --branch main \
  https://github.com/capstone1-irion/simulation.git CapstoneV2
cd CapstoneV2
```

## 2. 시스템 프로그램 — 사용자 직접 실행

다음 명령은 프로젝트 안이 아니라 Ubuntu의 `/usr`와 패키지 목록을 변경한다. 관리자 인증은 본인이 터미널에서 입력한다. 이미 다른 Gazebo/ROS를 쓰는 PC에서는 제거 예정 패키지가 있는지 확인하고, 관련 없는 프로그램을 자동 삭제하지 않는다.

먼저 공통 빌드 도구를 설치한다. `python3-venv`는 시스템 Python과 프로젝트 라이브러리를 분리하고, 개발 헤더는 native 컴파일에 쓰인다.

```sh
sudo apt-get update
sudo apt-get install build-essential cmake ninja-build git curl gnupg lsb-release \
  python3-dev python3-venv python3-pip ccache pkg-config \
  libssl-dev libxml2-dev libxml2-utils rsync unzip zip \
  libeigen3-dev protobuf-compiler libunwind-dev cppzmq-dev
```

Gazebo 저장소가 없는 PC에서만 다음 공식 저장소 등록을 실행한다. 변경 대상은 `/usr/share/keyrings/pkgs-osrf-archive-keyring.gpg`와 `/etc/apt/sources.list.d/gazebo-stable.list`다.[2]

```sh
sudo curl --connect-timeout 15 --max-time 120 \
  https://packages.osrfoundation.org/gazebo.gpg \
  --output /usr/share/keyrings/pkgs-osrf-archive-keyring.gpg
printf 'deb [arch=%s signed-by=/usr/share/keyrings/pkgs-osrf-archive-keyring.gpg] https://packages.osrfoundation.org/gazebo/ubuntu-stable %s main\n' \
  "$(dpkg --print-architecture)" "$(lsb_release -cs)" \
  | sudo tee /etc/apt/sources.list.d/gazebo-stable.list
sudo apt-get update
sudo apt-get install gz-harmonic libgz-sim8-dev libgz-transport13-dev \
  libgz-msgs10-dev libgz-plugin2-dev
```

`apt`는 저장소에서 현재 제공하는 patch 버전을 선택한다. 개발 PC에서 조회한 정확한 버전은 `config/sources.lock.json`에 기록했다. 다른 patch 버전을 설치했다고 동일 동작이 검증된 것으로 취급하지 않는다. 여기서는 ROS·실기체 cross compiler·Gazebo Classic을 설치하지 않는다.

## 3. 새 PX4 원본 — 프로젝트 안

기존 PX4 폴더를 복사하지 않는다. 이미 `external/PX4-Autopilot`이 있다면 삭제/덮어쓰기 대신 출처와 revision부터 확인한다. 아래 clone 명령은 목적지가 없는 첫 설치 전용이다.

```sh
mkdir -p external hermes/setup
chmod +x tools/bin/git
timeout --kill-after=5s 120s git clone --depth 1 --branch v1.17.0 \
  https://github.com/PX4/PX4-Autopilot.git external/PX4-Autopilot
```

고정 태그의 commit은 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`이다. SITL에 사용하는 submodule만 준비한다. 명령이 실패하면 그 상태를 보고 다음 단계로 넘어가지 않는다. 120초 제한은 무한 대기를 막기 위한 것이지, 다운로드 완료를 보장하는 시간이 아니다.

```sh
timeout --kill-after=5s 120s git -C external/PX4-Autopilot \
  submodule update --init --depth 1 --recursive \
  src/modules/mavlink/mavlink Tools/simulation/gz src/lib/events/libevents \
  src/drivers/gps/devices src/lib/heatshrink/heatshrink src/lib/crypto/monocypher \
  src/modules/uxrce_dds_client/Micro-XRCE-DDS-Client \
  src/lib/cdrstream/cyclonedds src/lib/cdrstream/rosidl
```

실패 뒤 재연결은 기존 다운로드 상태를 먼저 확인한 다음 수행한다. 다른 태그로 자동 우회하지 않는다. 이 checkout과 submodule의 소스·설정 파일을 직접 편집하지 않는다.

## 4. Python 가상환경 — 프로젝트 안

`.venv`에는 이번 프로젝트의 라이브러리만 넣는다. `requirements.lock`은 개발 시 설치한 버전을 고정한 파일이다. 시스템 Python에 `sudo pip`로 설치하지 않는다.

```sh
/usr/bin/python3 -m venv .venv
.venv/bin/python -m pip install --timeout 20 --retries 1 -r requirements.lock
```

활성화가 필요 없는 `.venv/bin/python` 형식을 사용하므로 다른 터미널/에이전트의 Python과 혼동을 줄인다. 이후 명령의 `PYTHONPATH=`는 외부 환경이 주입한 Python 검색 경로를 비운다. `-B`는 제품 폴더에 `__pycache__`를 만들지 않는다.

## 5. 빌드 — 비행하지 않음

개발 PC의 승인된 통합 검증에서는 빌드까지 완료했다. clone에는 빌드 산출물이 없으므로 새 PC는 의존성 준비 후 다음 명령으로 빌드한다. 새 개발 변경의 검증을 진행할 때는 합의된 최종 통합 실행에 빌드를 포함하고 중복 실행하지 않는다.

```sh
PYTHONPATH= .venv/bin/python -B tools/build.py --jobs 4
```

`tools/build.py`는 원본 PX4를 `hermes/build/px4`, V2 native를 `hermes/build/native`에 빌드한다. PX4 원본 XML에 맞는 Python dialect는 `hermes/generated/px4_mavlink.py`에 만든다. 빌드가 다운로드하는 추가 의존성도 있을 수 있으며 Git 연결은 `tools/bin/git`이 호출별 120초로 제한한다. 실패하면 로그를 보존하고 자동 재빌드하지 않는다.

## 6. 첫 실행과 조작

아래는 **빌드와 검증 상태를 확인한 뒤 사용하는 운영 명령**이다. 실행 예시이지 성공 기록이 아니다.

배터리 선택지를 보는 명령은 설치·연결·비행을 하지 않는다.

```sh
PYTHONPATH= .venv/bin/python -B main.py profiles
```

지상에서 시작한다. `--gui`를 빼면 창 없는 headless 실행이다.

```sh
PYTHONPATH= .venv/bin/python -B main.py simulate --gui \
  --profile cmu_vah01_rpt000 --soc 0.95
```

준비 후 같은 터미널에 다음 명령을 한 줄씩 입력한다.

| 명령 | 의미 |
|---|---|
| `status` | 운영 상태·최근 PX4 관측·전처리 준비 상태 조회 |
| `takeoff` | 원본 preflight가 성공할 때만 이륙 요청. 약 3 m 목표 |
| `fault 1 0.9 3` | 모터 1의 명령 각속도에 0.9를 3 SIM 초 적용 |
| `clear` | 현재 고장 해제 요청 및 적용 확인 |
| `pause` / `resume` | 시뮬레이션 시간 정지/재개 |
| `land` | 착륙·자동 Disarm 확인 |
| `quit` | 필요한 착륙을 시도하고 소유 자원 종료 |

고장은 정상 기준 배터리에서만 허용한다. pause 중에는 새로운 고장 조작을 받지 않는다. `clear`는 고장 배율을 해제하는 명령이지 통신/입력 오류를 지우는 명령이 아니다. 오류 뒤에는 해당 run을 보존하고 새 실행으로 시작한다.

`simulate` 시작만으로 자동 무장하지 않는다. 자동 실험은 별도 명령으로 명확히 구분한다.

```sh
PYTHONPATH= .venv/bin/python -B main.py experiment normal
PYTHONPATH= .venv/bin/python -B main.py experiment motor
PYTHONPATH= .venv/bin/python -B main.py experiment battery --profile cmu_vah01_rpt013 --soc 0.95
```

각 줄은 **독립 비행**이다. 처음부터 셋을 한꺼번에 붙여 실행하지 않는다. 앞 실행이 정상 종료된 것을 확인한다. 모터 시나리오는 기준 배터리, 1번 모터 0.9 배율 3 SIM 초다. 기본 시나리오의 변경은 `capstone/scenario.py`에서 한다.

실제 기체에는 이 CLI를 연결하지 않는다. 수집 외의 제어/배터리 주소는 소유 SITL의 loopback으로 한정된다. `COM_RC_IN_MODE=4`는 자율 SITL에서 RC stick 입력을 사용하지 않기 위한 run 설정이다. 센서 검사·GCS 링크 failsafe를 끄거나 force-arm하지 않는다. GCS heartbeat는 `scenario.py`의 별도 송신자가 담당한다.

## 7. 저장 위치와 종료

성공/실패를 포함한 각 실행은 `hermes/runs/<run-id>/`에 남는다.

| 경로 | 내용 | AI 입력 여부 |
|---|---|---|
| `telemetry/mavlink_raw.jsonl` | 수신 데이터그램과 디코딩 원문 | 전처리를 거친 관측만 사용 |
| `telemetry/summary.json` | 수집 건수·오류 | 품질 관리 |
| `groundtruth/run.json` | 프로파일·SOC·원본 revision·실행 설정 | 정답/관리 전용 |
| `groundtruth/events.jsonl` | 요청과 관측된 이륙·착륙·고장 이벤트 | 정답 전용 |
| `groundtruth/motor_battery.jsonl` | 중계 전후·joint·배터리 모델값 | 정답 전용 |
| `px4.log`, `gazebo.log`, `feed.log` | 프로세스 진단 | 사용하지 않음 |
| `cleanup.json` | 종료·강제 신호·잔류 프로세스 여부 | 품질 관리 |
| `rootfs/log/` | PX4가 만든 ULog | 별도 사후 참고; 이번 replay 입력은 아님 |

`Ctrl+C`도 종료 경로를 수행한다. 우선 착륙을 시도하지만 추락/단절 상황의 안전 착륙을 보장하지 않는다. `cleanup.clean=false`이면 정상 종료로 표시하지 않는다. `killall`, 전역 `pkill`, 출처 불명 `/tmp` 삭제는 하지 않는다.

원본 PX4가 자체 생성하는 `/tmp/px4_lock-31`, `/tmp/px4-sock-31`은 원본 동작을 유지한다. 시작 전 존재하면 보존하고 실행을 거부한다. 종료 후에는 이 실행이 기록한 UID/type/inode와 소유 프로세스 종료를 확인한 파일만 회수한다. 프로젝트가 만든 일반 로그/캐시/임시 파일은 run 안에 둔다.

## 8. 수집·재생·전처리만 사용하기

이 명령들은 비행 시나리오를 실행하지 않는다. `collect`는 수신 전용이므로 스트림 요청·heartbeat도 보내지 않는다. 실시간 송신자의 별도 설정과 실기체 연결 승인은 운영자 책임이다.

```sh
PYTHONPATH= .venv/bin/python -B main.py collect --port 14560 \
  --out hermes/manual-capture --system-id 1 --duration 30
```

실행 중인 V2 수집기와 같은 포트를 공유하지 않는다. default common dialect가 모르는 pinned PX4 메시지가 필요하면 `--decoder hermes/generated/px4_mavlink.py`를 지정한다.

닫힌 V2 수집 기록을 새 외피 파일에 순서대로 읽거나, 바로 특징으로 만든다. 아래 `<run-id>`는 실제 폴더 이름으로 바꾼다.

```sh
PYTHONPATH= .venv/bin/python -B main.py replay hermes/runs/<run-id>/telemetry \
  --out hermes/replay.jsonl
PYTHONPATH= .venv/bin/python -B main.py preprocess hermes/runs/<run-id>/telemetry \
  --firmware px4_gz --out hermes/features.jsonl
```

기업 DataFlash는 현재 항목·단위·기록 주기 참고자료이며 학습/시험 입력이 아니다. 다음은 선택적 재생 기능의 사용 예시이지 설치 필수 단계나 BIN 분석 창 확보 지시가 아니다. 원래 파일을 읽기만 한다.

```sh
PYTHONPATH= .venv/bin/python -B main.py preprocess /path/to/flight.BIN \
  --firmware arducopter_4_4 --out hermes/company-features.jsonl
```

기존 출력 파일은 덮어쓰지 않는다. BIN의 `TimeUS`, PWM 명령과 PX4 각속도 명령, 진동 지표는 서로 다르다. 상세 의미와 결측 규칙은 `docs/데이터계약.md`를 따른다. `ready`는 입력 준비 상태일 뿐 정상/고장 판정이 아니다.
